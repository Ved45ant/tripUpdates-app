# Live Trip Updates — Ordered, Resumable, Back-Pressured Fan-Out

Case Study 4. Cabs publish LOCATION, STATUS and SOS events. Employees, admins and security operators receive them live over WebSocket: in order per trip, with resume after a disconnect or a node crash, and with a slow client unable to slow the others. Tenant isolation is enforced on every subscription.

Stack: Java 21, Spring Boot 3.2 (Tomcat with virtual threads), Redis (Lua scripts and pub/sub), PostgreSQL, nginx, Docker Compose.

- Design and failure modes: [`docs/DESIGN.md`](docs/DESIGN.md)
- Test and load-run results: [`docs/VALIDATION_REPORT.md`](docs/VALIDATION_REPORT.md)

## Run

Requires Docker.

```bash
ENTRY_PORT=8080 docker compose up -d --build     # postgres, redis, 3 gateways, nginx → http://localhost:8080
```

Set `ENTRY_PORT` to any free port if 8080 is taken. Gateways are also exposed directly on 8091–8093.

To seed 2,000 extra cabs and trips for load testing, set `SEED_LOAD_CABS=2000` on the first start (the seed runs only on an empty database; `docker compose down -v` clears it).

## API

- `POST /api/v1/auth/login` — body `{"username": "<user id>", "password": "…"}` → `{token, …}`
- `POST /api/v1/auth/cab-token` (admin or operator) — body `{"cabId": "…"}` → cab device token
- `POST /api/v1/events/{location|status|sos}` (cab token) — body `{eventType, eventId, cabId, tripId, timestamp, payload}` → `202 Accepted`. `eventId` is required; a repeated `eventId` returns `202` without creating a new event.
- WebSocket `/ws/updates?token=<user JWT>`. Client frames: `{"action": "SUBSCRIBE" | "RESUME" | "UNSUBSCRIBE", "topic": "trip:<id>", "lastSeq": N}`. Server frames: `ACK`, `EVENT`, `SNAPSHOT`, `ERROR`.

Postman collection: [`postman/TripUpdates.postman_collection.json`](postman/TripUpdates.postman_collection.json) (HTTP requests; the WebSocket flow is in the demo client).

## Assumptions

- One Redis instance with AOF persistence. It is the single point of failure; there is no Sentinel or Cluster.
- `eventId` is generated by the cab and is unique per event. The server remembers it for 5 minutes per topic.
- The JWT signing secret comes from `JWT_SECRET`. Compose sets a demo value; change it for any real use.
- Users and passwords in the seed data exist for the demo only.

## Trade-offs

- **Ordering is per trip (per topic)**, not global.
- **STATUS and SOS are never dropped.** LOCATION is latest-wins, so a slow client gets the newest position, not every position.
- **Resume uses a bounded buffer** of the last 100 STATUS/SOS events per topic. A client further behind than that receives a snapshot of the current state.
- **At-least-once delivery on the wire, deduplicated at the client** by `(topic, seq)`. No exactly-once transport.
- Not built: Redis high availability, Kafka, multi-region deployment. Full list: [`docs/DESIGN.md`](docs/DESIGN.md) §8.
